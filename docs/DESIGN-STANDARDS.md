# Unified Router 设计与交互规范

> 这份文件是**规则源**：设置页怎么长、数据什么时候读、文案怎么写、六个渠道为什么必须长得一样。
> 每条规则后面标注它的由来（用户报障 / 实测结论 / 真实缺陷），以及对应的回归用例。
> 改 UI 或加渠道时**先读这里**，不要再按单点反馈临时改。
>
> 覆盖版本：0.3.0 起（2026-11-18 定稿）。相关文档：[AGENTS.md](../AGENTS.md)（工程约定）、
> [docs/CATALOG-AUDIT.md](CATALOG-AUDIT.md)（目录与上游差异）、[docs/architecture.md](architecture.md)（架构）。

---

## 0. 一句话原则

**同一个信息只出现一次；同一个动作在每个渠道都在同一个位置；用户不该为了看到数据去点任何东西。**

---

## 1. 信息架构：六个渠道必须是同一套骨架

### 1.1 打开设置页时的优先顺序

1. **定位问题。** 渠道网格显示当前选择、连接状态和账号、模型数量。进入上次查看的渠道。
2. **选择模型。** 打开设置或切换渠道后默认显示模型目录。模型页查目录、控制模型显示、调参数。
3. **管理账号与渠道。** 账号与额度页显示套餐、剩余额度和最近更新时间。有多个百分比窗口时摘要显示最紧张的窗口。展开「管理」查看额度包、重置时间、奖励和维护操作。渠道页负责提供方开关及连接表单。

### 1.2 统一界面

- 账号池与自管账号渠道使用「模型」「账号与额度」「渠道」。纯 API 渠道使用「模型」「渠道」。各分区共用渲染器。
- 账号一律使用列表行，行内提供指标、可用的开关和管理入口。移除账号与退出登录都在行内二次确认。
- 模型一律使用列表行，显示名称与 ID，支持搜索。普通目录分页，Raccoon 的免费与订阅目录各显示在自己的组里。可调模型使用共同的「参数」入口。保存成功或失败后保留当前编辑位置。
- 渠道提供方开关和连接都使用相同的设置行。仅提供实际支持的操作。账号或 API Key 未配置时，从相关分区直达对应表单。
- 每个分区的主操作放在标题右侧。页头「刷新」负责账号与额度，模型目录的刷新入口位于模型分区。

## 2. 数据加载与持久化

| 规则 | 回归覆盖 |
|---|---|
| 宿主启动触发首次采集，之后每 60 秒调度所有渠道的账号与额度。同一资源在途时合并刷新，其余渠道和资源独立提交。宿主独立模式每 60 秒检查到期凭据。 | `test/host.test.mjs` 后台调度与冷启动失败恢复测试 |
| 最近结果以公开字段投影原子写入 profile 状态目录的 `dsh-unified-router/settings.json`。部分失败时保留对应账号最后成功的额度和更新时间，显示「上次额度」。 | 同上，含重启恢复、凭据过滤和删除竞态 |
| 可见设置页每 5 秒读取进程内快照，聚焦或重新可见时立即读取。数据无变化时返回游标。打开页面、切换渠道和读取快照不触发额度上游请求。 | `test/web-client.test.mjs` 宿主快照测试 |
| 浏览器首屏恢复上次渠道和最近值。空态区分正在读取、读取失败、确实没有账号。已有数据继续显示，账号行提供刷新时间和失败状态。 | 本地缓存和首屏读取测试 |
| 手动刷新入队后立即返回，界面随下一次快照读取更新。登录、退出、账号设置、签到和奖励操作完成后更新受影响的快照。进行中的旧响应不能撤销写操作。 | 后台刷新与写入竞态测试 |
| 原有账号及模型设置 RPC 等待后端就绪，最多 15 秒。首次读取失败时仍可退避重试。 | `test/host.test.mjs` 和 `test/web-client.test.mjs` |

### 2.1 每日签到

- 独立模式由宿主自动签到，包含 Loomy、Qoder 中国版、TRAE 和 WorkBuddy。共用模式的账号池签到由原 Channel Pack 后端调度，Unified Router 调度 WorkBuddy。
- 宿主运行期间会跨日调度。Loomy、TRAE 和 WorkBuddy 按 UTC+8 日界，Qoder 中国版每日 10:00（UTC+8）进入新周期。Raccoon 的每日积分由上游发放。商汤 Token Plan 使用 API Key 管理模型和调用参数。
- 按渠道、账号和签到周期先写入提交记录，再请求上游。自动签到与设置页手动签到共用记录。账号行显示「已签到」「签到失败」或「签到待确认」等实际状态。明确停在状态预检的账号可隔一段时间再查，已发出领取请求的账号留待下个周期。成功时刷新相应额度快照。
- 账号与额度分区显示自动签到状态。宿主配置项 `autoCheckin: false` 关闭 Unified Router 的自动签到。手动签到仍使用同一份记录。

## 3. 模型目录与命名

| 规则 | 由来 | 回归用例 |
|---|---|---|
| 目录**只认上游**（`listAllModels()` 全量、不套黑名单）；黑名单只标记 `disabled` | 黑名单残留把已下架模型复活成幽灵行（`qwen3.8-max`） | `test/model-blacklist-hygiene.test.mjs` |
| 成功的远端目录按渠道和 profile 落盘。重开读上次目录，刷新失败保留该目录；没有成功记录才用内置目录。只有本轮真拉成功的目录才剪枝 | 断网或重开时仍能查看目录和参数 | `test/backend.test.mjs` 和 `test/model-blacklist-hygiene.test.mjs` |
| 模型搜索覆盖完整目录，默认启用优先，先排序再分页 | 已启用模型打开即见，保留按目录顺序查看的入口 | `test/model-selection-ui.test.mjs` |
| **默认启用与「恢复推荐」使用同一规则**。无手动覆盖时跳过有明确后继的旧版和有可比替代的型号。「恢复推荐」清除模型开关覆盖，目录始终保留手动开关 | 用户首次打开即可用推荐列表，也可以挑选其他型号 | `test/backend.test.mjs` 和 `test/model-selection-ui.test.mjs` |
| 型号依据调用 ID 和已核实的渠道别名识别。替代关系参考发布资料与同口径编码或智能体评测，按各渠道自己的额度倍率、上下文和图像能力筛选。同任务替代型号的倍率至少低三分之一才默认关闭原型号。官方参考倍率标「参考」 | 同一模型在各家渠道的消耗不同，免费与订阅目录独立 | `lib/model-catalog.js` 与 `test/model-rate-badge.test.mjs` |
| 参数显示适配器用于 DSH 的上下文、输出量、思考和图片设置。上游声明优先，渠道负责协议映射。缺少图片能力时省略图片结论 | 默认档和实际调用保持一致 | `test/backend.test.mjs` |
| **同名模型（如 Raccoon 免费/订阅）必须显示模型 id**；其它情况可只在重名时显示 | 免费/付费两侧展示名相同，只有 `-p` 后缀能区分 | 渲染核对（窄屏 id 换行显示） |
| **倍率只由选择器原生 badge 显示**，`name` 里不得再拼「· x0.75 / · 免费」 | 用户截图：「完全冗余」 | `test/model-rate-badge.test.mjs` |
| 设置列表和会话选择器统一清理 ID 格式的展示名，即使上游的名称与请求 ID 不同。内部代号（`qmodel_38max` / `qfmodel`…）使用已知别名，请求 ID 原样保留 | 「模型名显示的是内部代号」 | `test/qoder-cli.test.mjs` 别名用例 |

## 4. 文案

1. **界面只写数据、状态、动作**。禁止说明性段落与防御性句式（「请勿视为…」「不代表…」「以上游为准」「请先在 X 中 Y 再回来」）。
2. 更新状态写「更新中…」或「显示上次结果」。默认参数展示插件用于 DSH 的档位或数值。
3. 故障只写一句短语 + 一个动作（`读取失败` + `重试`）。
4. 单位与数字：余额/额度用千分位 + tabular-nums，数字字号大于标签。

回归：`test/web-client.test.mjs` 的文案类断言 + 逐屏渲染核对。

## 5. 视觉与布局

| 规则 | 说明 |
|---|---|
| 只用 `styles.js` 里的 `--eac-*` 令牌（颜色/间距/圆角/字阶），业务分支不写魔法值 | 间距走 4/8 网格 `--eac-s1…s6` |
| 渠道选择器是**自动换行的小卡片网格**（`repeat(auto-fill,minmax(150px,1fr))`），**禁止横向滚动条** | 用户：「最上面是左右拖动的滚动条，很难看」 |
| 重复条目用**列表**使用共用列表行；卡片只用于「一组互不相同的设置项」 | 账号/模型都是列表 |
| 强调色只用于主 CTA 与选中态；状态色只表达语义 | 反 AI 廉价感 |
| 以 DSH 固定上限 800×800 的设置弹窗为验收基准，扣除侧栏和边距后插件区宽约 560px。常规宽度为三列渠道卡，≤470px 为两列。比正常弹窗更窄时，倍率与标记另起一行 | 保持模型名、参数入口和倍率可读 |
| 模板字面量（`styles.js` 的 CSS）内部**不得出现反引号** | 曾把设置页整页搞白屏 |

## 6. 加新渠道 / 改界面的检查清单

1. 分区是否符合 §1.2 的渠道能力与命名？
2. 账号是否列表行 + 展开区？状态徽标是否在固定位置？
3. 模型是否按易读名称、实际参数和当前倍率构成列表行，启用优先是否在分页之前？
4. 首屏是否会读到该渠道的账号与额度？失败时能否恢复最近快照？
5. 文案是否只有数据/状态/动作？有没有说明性段落？
6. 有没有对应的回归用例？渲染核对过亮/暗/窄三种？

## 7. Provider 设置接口

客户端 provider 在 `src/client/providers/index.js` 注册。账号池渠道可以只提供 `id`、`title`、`pack: true`、能力和模型分组，由 `providers/pack.js` 提供默认实现。自管渠道实现相同的视图接口。

| 接口 | 数据 |
|---|---|
| `statusFrom(state)` | `{ closed, accounts, totalAccounts?, models, label?, tone? }` |
| `accounts(state)` | `{ ready, failed, rows, actions?, login? }`。账号行提供 `id`、`name`，可带 `tags`、`metric`、`updatedAt`、`groups`、`toggle`、`form`、`actions`、`confirmation`。 |
| `models(state)` | `{ groups }`。每组提供 `id`、`rows`，按需设置 `title`、`source`、`actions`。行使用 `provider:modelId` 作为唯一键，按能力声明 `toggle` 和 `editor`。 |
| `channel(state)` | 渠道设置行数组。可声明开关、连接表单或跳转动作。 |
| `snapshot` | 自管渠道可声明资源方法、快照读取状态、批量投影 `apply` 和进入渠道时的响应投影 `fromRead`。用 `keep` 声明切换渠道时继续保留的状态字段。 |
| `createActions(context)` | 专有动作的可选入口。视图用 `call: [action, ...args]` 调用动作。 |

渲染统一通过 `panels-core.js` 与 `kit/`。provider 提供公开数据、能力及动作描述。表单和编辑器通过已有的类型接入。

宿主侧在 `lib/settings-providers.js` 注册资源，提供采集与公开投影，有需要时合并上次成功结果。`lib/settings-snapshots.js` 负责调度、版本游标、并发和落盘。`settings.snapshot` 返回 `{cursor, entries}`，每个资源是 `{at, stale, value}`。`settings.refresh` 接受 `{provider}`，提交该渠道的后台采集。直接 RPC 仍用于账号与模型设置、登录、刷新模型目录等显式动作。

独立推理后端 provider 挂载位于 `src/backend/providers/`。模块返回按 provider ID 索引的适配器及账号维护函数。普通账号池渠道可用 `pooledCredentials` 复用选号、限流、凭据续期与账本归属。新增源码模块后在对应注册表和构建入口登记，并按宿主白名单开放所需 RPC。
